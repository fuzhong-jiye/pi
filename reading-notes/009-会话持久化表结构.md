# 009 - 会话持久化"表结构"

## 一句话定位

Pi **没有数据库、没有 SQL**。持久化用的是 **append-only 的 JSONL 文件**，每个会话一个 `.jsonl`，**每行一条记录**，整体是一棵 **event-sourcing 风格的会话树**。所谓"表结构"，就是这些行记录（`SessionTreeEntry`）的 schema。

核心目录：`packages/agent/src/harness/session/`

| 文件 | 职责 |
|------|------|
| `jsonl-storage.ts` | JSONL 文件读写、解析、append（落盘实现） |
| `jsonl-repo.ts` | 会话仓库：create/open/list/delete/fork、路径编码 |
| `session.ts` | `Session` 高层 API + `buildSessionContext`（把树重建成消息） |
| `memory-storage.ts` / `memory-repo.ts` | 纯内存实现（测试 / 临时会话，非落盘） |
| `repo-utils.ts` | ID、时间戳、fork 取分支 |
| `uuid.ts` | 自实现 UUIDv7（时间有序） |
| `../types.ts` | 所有 entry 类型定义（line 334-447） |

  └── --Users-albaohlson-Documents-poc-pi--/   # 按 cwd 编码的目录（encodeCwd）
        └── 2026-06-03T12-30-00-000Z_<uuidv7>.jsonl

- `CONFIG_DIR_NAME` = `.pi`（可被 package.json 的 `piConfig.configDir` 覆盖），agent 根目录 `~/.pi/agent/`。
- **cwd 编码**（`jsonl-repo.ts:34` `encodeCwd`）：去掉开头斜杠，把 `/ \ :` 全替换成 `-`，两端包 `--`。**同一工作目录的会话归到同一子目录**，`list({cwd})` 据此快速筛选。
- 文件名 = `时间戳(:.替换成-)_会话id.jsonl`，时间戳前缀让文件名天然按时间排序。

## 二、文件格式：第 1 行是表头，其余每行一条 entry

### 表头行（SessionHeader，`jsonl-storage.ts:8`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | `"session"` | 固定 |
| `version` | `3` | **schema 版本，必须是 3**，否则报 `unsupported session version` |
| `id` | string | 会话 id（uuidv7） |
| `timestamp` | ISO string | 创建时间 |
| `cwd` | string | 会话工作目录 |
| `parentSession` | string? | 父会话文件路径（fork 时记录来源） |

解析严格：第一行必须能解析成合法 header，否则整文件视为 `invalid_session`（`list` 时会跳过这类坏文件，`parseHeaderLine`）。

### 记录行（SessionTreeEntry）

所有 entry 共享基类（`types.ts:334`）：

| 公共字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | 判别式（discriminator） |
| `id` | string | entry id，**uuidv7 前 8 位**，文件内唯一 |
| `parentId` | string \| null | 父 entry id；null 表示根 |
| `timestamp` | ISO string | 写入时间 |

## 三、"表"清单：10 种 entry 类型

`SessionTreeEntry` 是一个判别联合（`types.ts:404`）。把每种 type 当成一张"表"：

| type | 专有字段 | 作用 |
|------|----------|------|
| `message` | `message: AgentMessage` | **主体**：一条 user/assistant/tool 消息（含 provider/model） |
| `thinking_level_change` | `thinkingLevel: string` | 切换思考档位 |
| `model_change` | `provider`, `modelId` | 切换模型 |
| `compaction` | `summary`, `firstKeptEntryId`, `tokensBefore`, `details?`, `fromHook?` | 上下文压缩点：摘要 + 从哪条起保留原文 |
| `branch_summary` | `fromId`, `summary`, `details?`, `fromHook?` | 跳转分支时对旧分支的摘要 |
| `custom` | `customType`, `data?` | 扩展自定义数据（不进消息流） |
| `custom_message` | `customType`, `content`, `display`, `details?` | 自定义消息（可进消息流，`display` 控制是否展示） |
| `label` | `targetId`, `label?` | 给某条 entry 打/清标签（label 为空即删除） |
| `session_info` | `name?` | 会话命名（`type` 是 legacy 名，保留兼容） |
| `leaf` | `targetId: string \| null` | **指针记录**：把"当前活跃叶子"移动到 targetId |

> 关键点：**所有变更都是 append**——改模型、改思考档、命名、压缩、打标签，统统是追加一行新 entry，**从不原地修改历史**。这就是 event sourcing：当前状态由"重放全部 entry"推导出来。

---

## 四、树模型与"当前叶子"

### parentId 构成树
每条 entry 用 `parentId` 指向上一条，形成链/树。`getPathToRoot(leafId)`（`jsonl-storage.ts:275`）从叶子沿 parentId 一路回溯到根，得到一条**分支路径**——这才是要喂给模型的上下文。

### leaf entry = 可持久化的"HEAD 指针"
活跃叶子不是靠"最后一行"隐式决定，而是显式记录：
- 普通 entry 写入后，叶子 = 该 entry 的 `id`（`leafIdAfterEntry`）。
- `leaf` 类型 entry 写入后，叶子 = 它的 `targetId`（可为任意历史 entry，甚至 null=回到空）。
- `setLeafId()`（`jsonl-storage.ts:226`）就是 append 一条 leaf entry 来"移动 HEAD"。

这让**分支跳转本身也被持久化、可追溯**，类似 git 的 reflog。

### 分支与 fork
- **同文件内分支**：`moveTo(entryId, summary?)` 把叶子移到某历史 entry，之后的 append 就长出新分支；可选地写一条 `branch_summary` 记录对旧分支的总结（`session.ts:232`）。
- **跨文件 fork**：`JsonlSessionRepo.fork`（`jsonl-repo.ts:133`）新建一个 `.jsonl`，header 的 `parentSession` 指向源文件，把源分支的 entry 复制进去。
  - `getEntriesToFork`（`repo-utils.ts:32`）：`position:"at"` 从目标 entry 起；默认 `"before"` 要求目标是 **user 消息**，从其 parent 起（即"在这条用户消息之前重开"）。

## 五、重建上下文：buildSessionContext

`buildSessionContext(pathEntries)`（`session.ts:21`）把一条分支路径还原成 `SessionContext { messages, thinkingLevel, model }`：

1. 顺序扫描，遇到 `thinking_level_change` / `model_change` / assistant message 更新当前档位与模型；遇到 `compaction` 记下压缩点。
2. 生成 messages：
   - `message` → 直接取出
   - `custom_message` → 重建为自定义消息
   - `branch_summary` → 重建为分支摘要消息
3. **压缩处理**：若存在 compaction，则先放一条压缩摘要消息，再**只保留从 `firstKeptEntryId` 起、以及压缩点之后**的 entry。压缩前更早的原文被摘要替代，省 token。

> 即：**磁盘存全量历史（含被压缩的原文），喂给模型时按 compaction 规则裁剪**。历史不丢，上下文可控。

## 六、存储抽象与可替换后端

`SessionStorage<TMetadata>` 接口（`types.ts:433`）定义了 getLeafId/setLeafId/appendEntry/getEntry/findEntries/getLabel/getPathToRoot/getEntries 等。两套实现：

| 实现 | 落盘 | 用途 |
|------|------|------|
| `JsonlSessionStorage` | ✅ JSONL 文件 | 生产 |
| `InMemorySessionStorage` | ❌ 仅内存 | 测试 / 临时会话 |

两者逻辑几乎一致（树回溯、label 缓存、leaf 指针），只差 append 是否 `fs.appendFile`。`SessionRepo` 同理有 `JsonlSessionRepo` / `InMemorySessionRepo`。**这层抽象让"持久化方式"可插拔**——理论上换 DB 后端只需实现接口。

### 内存索引
打开文件时（`loadJsonlStorage`）一次性读入全部行，构建：
- `entries[]` 顺序数组
- `byId: Map` 快速按 id 查
- `labelsById: Map`（重放 label entry 得到的当前标签）
- `currentLeafId`

之后读操作全在内存，写操作既 append 落盘又更新内存索引（`appendEntry`，`jsonl-storage.ts:250`）。

## 七、ID 方案：UUIDv7 + 截断

`uuid.ts` 自实现 **UUIDv7**（前 48 位是毫秒时间戳 → **时间有序**，利于按生成顺序排序、做文件名前缀）。
- 会话 id 用完整 uuidv7。
- entry id 用 **前 8 个 hex 字符**（`generateEntryId`），冲突则重试 100 次，再不行退回完整 uuid。文件内小规模下 8 位足够且更短。

## 设计要点回顾

1. **Append-only JSONL**：一行一记录，崩溃安全、易 diff、易回放、无需 DB。
2. **Event sourcing**：状态（模型/档位/标签/叶子）由重放 entry 推导，历史不可变。
3. **持久化的树 + leaf 指针**：分支跳转、fork、压缩都被记录，可追溯（类 git）。
4. **存全量、喂裁剪**：compaction 在读取时裁剪上下文，磁盘仍留原文。
5. **存储接口可插拔**：JSONL 与内存两实现共享同一接口。
