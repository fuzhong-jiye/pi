# 004 - 真正的"最小公共接口"：Agent Loop + TUI 双视角验证

## 回顾

003 号文档确认了 `AssistantMessage` 是**所有供应商字段的超集**。但这不是 agent loop 和 TUI 关心的抽象。它们各自只使用其中一小部分字段。那部分，才是所有 API 协议必须实现的**真正最小公共接口**。

## Agent Loop 实际访问了什么

对 `agent-loop.ts` 做全局搜索，得出的精确清单：

### 1. 消息级字段

| 字段 | 访问方式 | 用途 |
|------|---------|------|
| `message.role` | `msg.role === "assistant"` | 区分消息类型 |
| `message.stopReason` | `=== "error"` / `=== "aborted"` | 错误/中断处理 |
| `message.content` | `.filter()` / `.map()` | 遍历内容块 |
| `message.errorMessage` | 字符串读取 | 错误展示 |
| `message.model` | 字符串比较 | 模型追踪 |
| `message.usage` | `.input` / `.output` / `.totalTokens` | 用量统计 |

### 2. 内容块级字段

| 块类型 | 访问的字段 | 用途 |
|--------|-----------|------|
| `text` | `.text` | 提取文本内容 |
| `thinking` | `.thinking` | 提取思考内容（展示用） |
| `toolCall` | `.id`, `.name`, `.arguments` | 执行工具调用 |
| `image` | `.data`, `.mimeType` | 渲染图片 |

代码证据：

```typescript
// agent-loop.ts — 找到工具调用
const toolCalls = message.content.filter((c) => c.type === "toolCall");

// agent-loop.ts — 判断停止原因
if (message.stopReason === "error" || message.stopReason === "aborted") { return; }

// agent-session.ts — 提取文本
const textBlocks = content.filter((c) => c.type === "text");
return textBlocks.map((c) => c.text).join("");

// compaction.ts — 三种块都处理
if (block.type === "text") { /* block.text */ }
else if (block.type === "thinking") { /* block.thinking */ }
else if (block.type === "toolCall") { /* block.name, block.id */ }
```

### 3. 事件流协议

```typescript
// agent-loop.ts — streamAssistantResponse()
case "start":          // 流开始
case "text_start":     // 文本块开始
case "text_delta":     // 文本增量
case "text_end":       // 文本块结束
case "thinking_start": // 思考块开始
case "thinking_delta": // 思考增量
case "thinking_end":   // 思考块结束
case "toolcall_start": // 工具调用开始
case "toolcall_delta": // 工具调用增量
case "toolcall_end":   // 工具调用结束
case "done":           // 流成功终止
case "error":          // 流错误终止
```

### 4. 工具执行相关

```typescript
// AgentLoopConfig 中暴露的接口
toolCall.id           // 工具调用 ID
toolCall.name         // 工具名称
toolCall.arguments    // 工具参数
```

## TUI 层实际访问了什么

`assistant-message.ts` — 完整的 assistant message 渲染组件（65 行核心逻辑）：

```typescript
// 唯一的内容块处理逻辑
for (let i = 0; i < message.content.length; i++) {
  const content = message.content[i];
  if (content.type === "text" && content.text.trim()) {
    this.contentContainer.addChild(new Markdown(content.text.trim(), ...));
  } else if (content.type === "thinking" && content.thinking.trim()) {
    if (this.hideThinkingBlock) {
      // 显示 "Thinking..." 占位文本
    } else {
      this.contentContainer.addChild(new Markdown(content.thinking.trim(), ...));
    }
  }
}

// 错误/中断展示
if (message.stopReason === "aborted") { /* 显示 message.errorMessage */ }
else if (message.stopReason === "error") { /* 显示 message.errorMessage */ }

// 检查是否有 toolCall（决定渲染模式）
const hasToolCalls = message.content.some((c) => c.type === "toolCall");
```

`interactive-mode.ts` — toolCall 处理：

```typescript
for (const content of this.streamingMessage.content) {
  if (content.type === "toolCall") {
    new ToolExecutionComponent(
      content.name,       // 工具名
      content.id,         // 调用 ID
      content.arguments,  // 参数
    );

```

| 字段 | TUI 引用 |
|------|---------|
| `content[i].type === "text"` + `.text` | Markdown 渲染 |
| `content[i].type === "thinking"` + `.thinking` | 思考折叠/展开渲染 |
| `content[i].type === "toolCall"` + `.name` / `.id` / `.arguments` | 工具执行组件创建 |
| `content[i].type === "image"` + `.data` / `.mimeType` | 图片渲染 |
| `message.stopReason` | 错误/中断展示 |
| `message.errorMessage` | 错误信息展示 |

**TUI 同样零引用** `thinkingSignature`、`redacted`、`textSignature`、`thoughtSignature`。

## 绝对不能碰的字段（agent + TUI 双验证）

在整个 agent / coding-agent 代码中**零引用**的供应商专有字段：

| 字段 | 所属供应商 | agent 层引用次数 |
|------|-----------|-----------------|
| `thinkingSignature` | Anthropic | 0 |
| `redacted` | Anthropic | 0 |
| `textSignature` | OpenAI Responses | 0 |
| `thoughtSignature` | Google | 0 |
| `responseId` | 通用可选 | 0 |
| `responseModel` | 通用可选 | 0 |

**这六个字段对 agent loop 和 TUI 完全透明** — 它们只在 `packages/ai` 层的 `transformMessages` + `convertMessages` 中被处理。agent loop 只是原样存储和传递，TUI 只是遍历 `content[]` 时跳过不认识的类型。

## 结论：新增 API 协议到底要改什么

如果新协议能实现以下**最小契约**，agent loop 和 TUI 完全不需要改动：

1. **内容块**能映射为 `text` / `thinking` / `toolCall` / `image` 四种类型之一
2. **停止原因**能映射为 `stop` / `length` / `toolUse` / `error` / `aborted` 五种之一
3. **事件流**能产生 `text_start/delta/end`、`thinking_start/delta/end`、`toolcall_start/delta/end`、`done`、`error` 事件
4. **Message** 携带 `role`、`content`、`model`、`usage`、`timestamp`

超出这个契约的新数据 — 比如新协议的专有加密字段 — 可以加到 `AssistantMessage` 或内容块的**可选字段**中，agent loop 会自动忽略。

**所以全程只需要改 `packages/ai`：**
- 新增 provider 文件（实现 `stream()` + `streamSimple()`）
- 在 `register-builtins.ts` 注册
- 如果新协议有超出四种块类型之外的块类型 → 扩展 `AssistantMessage["content"]` 联合类型（agent 代码用 `c.type === "toolCall"` 这种精确匹配，不会误识别未知类型）
- 如果新协议有全新的供应商专有数据 → 在对应块类型上加可选字段
